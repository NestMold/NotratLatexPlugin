# v0.9 改造方案：单一文档模型 + 单一事务历史

> 目标方向：**B（建文档模型，双档从模型渲染）**
> 核心痛点：**撤销 / 重做不可预测**
> 约束：允许大改，只要体验对；源码绝不损坏仍是第一红线

---

## 0. 一句话结论

撤销不可预测不是「栈写错了」，是**根本没有一个东西叫「文档」**。

现在有三处各自为政的「当前内容」：

| # | 权威 | 谁在管 | 撤销栈 |
|---|---|---|---|
| 1 | `props.content`（LaTeX 源码串） | 宿主 React | 宿主自己的（不可见） |
| 2 | 源码档 `<textarea>` 的 value | 浏览器原生 | **浏览器原生栈** |
| 3 | 可视化档 `.wys-editroot` 的 DOM | contenteditable | `wysUndoRef`（整份源码快照） |

三份内容、三套历史、靠 **三个布尔标志**（`wysEditing` / `wysSelfEdit` / `wysHistOp`）互相打手势。
布尔标志是**边沿触发的便条**，不是计数器、不是队列 —— 任何一个便条被「错误的那个变化」消费掉，
结果要么是该重建没重建（DOM 与源码脱节），要么是不该重建却重建（光标丢、视口跳）。
而 `panels/editor.tsx:1629` 还有一条兜底规则：

```ts
if (!selfEdit && !histOp) { wysUndoRef.current = []; wysRedoRef.current = []; }
```

**误判一次，用户历史当场清空。** 这就是「有时能撤、有时说没有可撤、有时撤到别的分支」的全部来源。

方案 B 的本质：**把三份内容合成一份「文档」，把三套历史合成一套「事务日志」，两个视图降级为纯渲染器。**

## 1. 现状取证（全部可复核）

代码位置以当前工作区为准（`panels/editor.tsx` 2887 行，`server/wysiwyg.js` 541 行）。

### 1.1 数据流

```
宿主 props.content ──► wysRenderDoc(content) ──► HTML ──► innerHTML = html ──► .wys-editroot
        ▲                                                                          │
        │                                                                    用户打字
        └──────────── onChange(整份新源码) ◄── wysDomToTex + WYS.applyEdits ◄──────┘
```

- 真相是**源码串**，但 DOM 在编辑期间又被声明为真相（`wysEditing`）。
- 两端靠 `wysOrigRef`（渲染时的原文快照）判断「这块到底动没动」。
- 结构性动作（Ctrl+1 改层级、撤销）走的是：**整块重写源码 → 宿主回传 → `innerHTML` 全量重建 → 启发式接回光标**。

### 1.2 撤销栈的实际情况

| 位置 | 粒度 | 生命周期 |
|---|---|---|
| `wysUndoRef` / `wysRedoRef` (`editor.tsx:1008-1009`) | **整份源码快照**，上限 50 步 | 任何来自预览层之外的变化 → **整条清空** |
| 源码档 `<textarea>` | 浏览器原生 | 切档 / 重渲染即不可预期 |
| 宿主 | 未知 | 与插件历史完全不同步 |

### 1.3 五个具体病灶（对应「不可预测」的每一种观感）

1. **打字不在历史里。** 正文要等失焦 / Ctrl+S 才 `commitWys()`。所以「刚打完字按 Ctrl+Z」栈里没有这步。
   v0.8.17 加了 `wysCommitPending()` 打补丁（撤销前先强落一次盘）—— 这是补丁，不是修复：
   它本身又改了状态，再把 `wysSelfEdit` 手动复位，属于「用更多状态解释状态」。
2. **外部一改就清栈。** `editor.tsx:1629`。用户读作「刚才还能撤，现在说没有」。
3. **撤销 = 换头术。** 还原整份源码 + 重建整个 DOM。光标、滚动、编辑中的原子岛、折叠状态全靠重新接。
   而接回那套（`wysCaretRestore`）历史上曾整条静默失效过（`NodeFilter.SHOW_TEXT` 写成 `3` 的旧事故，
   注释还留在 `editor.tsx:2072` 附近）—— 说明启发式回接是不可靠的长期负债。
4. **重做链记的是闭包里的旧值。** `wysRedoRef.current.push(committed != null ? committed : content)`
   （`editor.tsx:1147`）—— 代码注释自己就写了「组合路径下闭包 content 还是打字前的旧值」。
   闭包取错 → 重做重放错的「改后状态」→ 用户读作「重做也不对」。
5. **越界还原。** 快照是整份文档，所以「撤销一步」会把**此后由别人做过的改动一起退掉**。
   这既是「撤到别的分支去」的观感，也是数据风险。

### 1.4 一个必须尊重的硬约束

`server/wysiwyg.js` 的这条不变式是**护稿底线**，v0.9 必须原样继承：

```js
applyEdits(src, []) === src          // 空编辑集必须逐字节还原
```

它存在的原因写在文件头：LaTeX 是编程语言，而渲染层是有损的（`\cite{x}` → `[1]`、
`\ref{fig}` → 「图 1」）。**由渲染结果反推源码 = 用户敲一次字就烧掉引用**。
所以 v0.9 的模型必须是**无损 CST**（保留空白、注释、折行、`*`、`[短标题]`、`\label`），
而不是会把 trivia 丢干净的抽象 AST。

同理，`data-s` / `data-e` 这些**行号**被这些下游依赖着，模型必须继续提供精确行号：

- 大纲面板与宿主导航：`gotoLine()` / `pendingReveal` / `notrat-outline-navigate`
- MCP 工具：`latex_outline`（`format: outline` → `{text, level, anchor}`）、`latex_parse` / `latex_validate`

## 2. 目标架构

```
                        ┌──────────── History（事务日志 + rebase）────────────┐
                        │                                                   │
   用户手势 ──► intent ─►│  Op[]  ──►  Doc.apply(ops)  ──►  Tx{ before, after, sel }
                        │                                                   │
                        └───────┬───────────────────────────────┬───────────┘
                                ▼                               ▼
                        Doc.source（唯一真相）          Doc.nodes（唯一投影源）
                                │                               │
                        host onChange                    ├──► 预览 DOM：按 node.id 定点打补丁
                                                         └──► 源码档：模型 → text
```

**三条不变量（v0.9 的宪法）**

1. **只有一份内容**：`Doc`。DOM 与 textarea 都是它的渲染产物，任何时刻都不许成为真相。
2. **只有一套历史**：`History`。两个视图的 Ctrl+Z 走同一个入口，看到的顺序完全一致。
3. **改一个块，就只碰一个块**：编辑不再触发任何全量重建（`innerHTML = ` 这条路径要删掉）。

## 3. 模块设计

### 3.1 `server/docmodel.js`（新增，无损 CST）

零依赖、Browser / Node 双端通用，构建方式沿用 `wysiwyg.js` 那条通路（见 §6）。

```ts
type Span = { from: number; to: number };            // 源码字符偏移，闭开区间

interface DNode {
  id: string;                 // 稳定 id（首次由 位置+内容哈希 派生，此后随节点走）
  kind: 'preamble'|'heading'|'para'|'math'|'float'|'code'|'bib'|'list'|'env'|'command'|'comment'|'blank'|'tail';
  span: Span;                 // 这一块在源码里的精确字符区间（含它自己的 trivia）
  lineFrom: number; lineTo: number;   // 0 基闭区间 —— 喂给大纲 / 宿主导航，契约不变
  cmd?: string; level?: number;       // heading
  prefix?: string; suffix?: string;   // 保住 \section* / [短标题] / \label
  raw: string;                // 原样子串（不重排、不重排空白）
}

interface Doc { source: string; nodes: DNode[]; version: number; }
```

对外 API：

```js
parse(source)            -> Doc          // 无损：serialize(parse(s)) === s（字节级）
serialize(doc)           -> string       // 唯一出口
applyOps(doc, ops)       -> { doc, tx }  // 纯函数；只有被 touch 的节点字节会变
reproject(doc)           -> doc          // 外部改动进来后重算 span / 行号 / id，但保留稳定 id
nodeAtLine(doc, line)    -> DNode | null // 仪表栏、大纲高亮、跳转用
```

**Op 集合（先做最小可用集，够覆盖现状所有编辑路径）**

```ts
type Op =
  | { t:'setText';     id:string; text:string }        // 块内文字（正文 / 标题）
  | { t:'setHeading';  id:string; cmd:string|null }    // Ctrl+1..6 / Ctrl+0（含多物理行段落合并）
  | { t:'splitPara';   id:string; at:number }          // Enter：段内换行 → 拆块
  | { t:'mergePara';   ids:string[] }                  // 段首 Backspace：合块
  | { t:'replaceRaw';  id:string; raw:string }         // 原子卡片（公式 / \cite / 表格）改源码
  | { t:'insertNode';  index:number; raw:string }
  | { t:'deleteNodes'; ids:string[] };
```

> 每个 Op 只允许触碰它自己的 `span`。这条由测试直接断言（§5）。

### 3.2 `server/txlog.js`（新增，事务历史）

```ts
interface Tx {
  id: string;
  label: string;                 // 「打字」「设为 subsection」「改公式」—— 用于 toast / 历史面板
  ops: Op[];
  before: string; after: string; // 字节级，用于自检与正确性
  sel?: Sel;                     // 撤销后要恢复的光标 / 视口
  at: number;
}

class History {
  commit(tx)                  // 新事务入栈，清 redo（标准语义）
  coalesce(tx, windowMs=400)  // 打字合并：同块连续输入并进同一个 tx
  undo(): Tx | null           // 返回「要撤销的那个 tx」，不直接改文档
  redo(): Tx | null
  rebase(extBefore, extAfter) // ⭐ 外部改动进来时调用 —— 绝不清栈
  gaps: number                // 因无法 rebase 而丢弃的步数（诚实告知用户）
}
```

`rebase` 是治愈「一改就清栈」的那味药：把外部改动当成一次 patch，
用三方文本合并（`before`/`after`/外部结果）把每条待撤销事务映射到新版本上。

- 能干净合并 → 历史完整保留（这是绝大多数情况：外部改动通常落在**别的块**上）。
- 合并冲突 → **只丢那一条**，`gaps++`，UI 明说「更早的 3 步已与磁盘版本分叉，无法撤销」
  （诚实 > 静默清空）。

`coalesce` 是治愈「刚打完字撤不动」的那味药：**第一次按键就有一个开着的 tx**，
400ms 空闲或离开该块才封口。于是任何时刻 Ctrl+Z 都必然有东西可撤。

### 3.3 渲染层：按 `node.id` 定点打补丁

现在是 `root.__latexHtml !== html` → `root.innerHTML = html`（全量重建）。
改为：

```ts
renderDoc(doc, env) -> { key: string, html: string }[]   // 每块一份，key = node.id
patchPreview(root, blocks)                               // 只操作 key 变了的 / 新增的 / 删除的
```

收益是连锁的：

- 改一个字 → 只 patch 一个文本节点 → **光标不可能丢**（不再需要 `wysCaretRestore` 那套偏移算术）。
- 撤销一步 → 只 patch 受影响的那一块 → **视口不跳、编辑态不炸**。
- 三个布尔标志（`wysEditing` / `wysSelfEdit` / `wysHistOp`）**全部删除** ——
  「谁改了」这件事由 `tx.id` 明确回执，不需要靠便条猜。

### 3.4 源码档：接进同一套历史

保留 `<textarea>`（不自研编辑器，风险最低），但：

- value 由 `Doc.source` 单向驱动；
- `input` 事件 → 计算最小 diff → 定位到节点 → 生成 `setText` / `insertNode` tx；
- `Ctrl+Z` / `Ctrl+Y` → `preventDefault()` → 走同一个 `History`。

**这一步做完，「源码档改的撤不掉 / 预览档改的源码档撤不掉」才真正消失。**
（Phase 5 再考虑换 CodeMirror 6 之类，纯 UX 升级，与撤销正确性解耦。）

## 5. 宪法级不变量（进 `npm run gate`，一条不过就不许发布）

1. `WYS.applyEdits(src, []) === src`（继承旧红线）
2. `serialize(parse(src)) === src`（新模块的无损红线，跑语料）
3. 每个 Op 只触碰自己的 `span`；未触碰节点的字节**逐字节**保留
4. `undo ∘ do = id`：任意本地操作序列撤销回起点，字节级相等
5. **打字后 400ms 内必有可撤销事务**（CTRL+Z 永不出现「没有可撤销的改动」）
6. 单块编辑的 DOM mutation 次数 ≤ 2（MutationObserver 断言 —— 防「偷偷全量重建」回归）
7. 每个节点的 `lineFrom/lineTo` 精确（大纲 / 宿主跳转契约不变）
8. 冲突时 `gaps` 必须被 UI 呈现（不许静默丢历史）

> 附带建议：现在的验收门里有若干**断言源码字符串**的用例
> （例：`.setup/check-v0811-edit.js` 里写死了 `endLine: s`，v0.8.13 改了实现就得改断言）。
> 这类断言把测试和实现耦合死了，改造期会持续误报。
> 建议把门逐步换成**行为断言**（直接调纯模块 + jsdom 观察 DOM），源码字符串只留少量「防回归指纹」。

## 6. 工程接缝（别踩这几个坑）

1. **单文件打包**：`npm run build`（`.setup/build-singlefile.js`）把 `panels/editor.tsx` 里的
   `/*__LPC__*/`、`/*__WYS__*/` 占位符替换成内核源码。新模块要照抄这条通路：
   加 `/*__DOC__*/`、`/*__TX__*/` 占位符 + 内联分支。
2. **绝对不许残留 `module.exports`**：内联后若残留，会覆盖宿主 `exports`，
   编辑器报「default 应为 function，实际为 object」（0.3.0 事故，脚本里已有硬检查）。
3. **导出语句不能有嵌套花括号**：内联正则用 `[^}]*` 匹配（wysiwyg 已有此约束）。
4. **版本号单一来源**：`manifest.json`，构建脚本读它；`server/index.js` 的 `VERSION` 由脚本对齐。
5. **受控组件语义**：`props.content` / `onChange` 是宿主回路。若宿主会**批量 / 延迟**回传，
   必须用 `tx.id` 回执去重，不能靠「值相等」判断（值相等 ≠ 是同一次变更）。

## 7. 风险与对策

| 风险 | 概率 | 对策 |
|---|---|---|
| 语料太薄（现在只有 `samples/*.tex`），无损 CST 在真实论文上翻车 | 高 | P1 之前先收 20–30 份真实 `.tex`（arXiv 源码 / 期刊模板）做语料；把「解析失败」当**测试失败**而不是崩溃 |
| CRLF / BOM / `verbatim` 里的 `%` / 多行标题 / `\end{document}` 后的垃圾 | 中 | 全部进 P1 用例；`serialize` 用原样子串拼接，不做任何规范化 |
| rebase 冲突策略过于激进（把用户历史搞乱） | 中 | 冲突即丢（fail-safe），并显式呈现 `gaps`；宁可少撤，不可撤错 —— 这条要保住 |
| 宿主自己也管撤销，与插件历史打架 | 中 | 编辑器聚焦期间插件持有文档；失焦时把最终状态同步出去。需与宿主约定（可查宿主契约文档） |
| 大文档 keyed patch 性能 | 中 | 先测再优化；后续可加块级虚拟滚动，与本次改造正交 |
| P3 改动面大（删三个标志 + 换重建路径） | 中 | 保留一条 `LEGACY_REBUILD` 逃生开关，一个版本后删除 |

### 9.2 实现期定下的契约（方案原文没写，必须记下来）

1. **末尾幽灵空行必须独占一个节点。**
   `src.split("\n")` 在以 `\n` 结尾时多一个恒为空串的尾元素。只要它和前面的行并进同一节点，
   那个节点的 raw 就同时具备「以换行结尾」和「末行无换行」两种写法 —— `"\n"` 到底占几行，**字符串编码本身是有歧义的**。
   解法不是聪明解读，而是结构上禁止：末尾幽灵行单独成节点，任何块 / 空行段只到 `bodyEnd` 为止。
   （这条不立，`countLines` 就会少算一行，`\n` 这种最普通的文件都会当场报「平铺不完整」。）

2. **片段 ≠ 整篇：`replaceRaw` / `insertNode` 切出来的片段要丢掉末尾幽灵行。**
   整篇 parse 需要幽灵行（行数才算得准），片段拼接不需要（留着就凭空多一个空行）。两者的区别必须显式处理。

3. **`textOf(node)` 是 `setText` 的入参口径。**
   标题只有中间那段可编辑（前后缀 `\section*{` / `}\label{..}` 是命令结构，不是内容），其余块是整块正文。
   少了这个口子，调用方就得自己分辨「标题取 title、其余取 body」—— 迟早有人把含命令的整行塞进 `setText`，
   把命令套两层写坏源码（P1 测试当场抓到 4 份语料就是这样翻车的）。

4. **换层级时星号必须跟着走。** `\section*{甲}` → subsection 必须是 `\subsection*{甲}`。
   丢了星号等于把「不编号的节」悄悄变成编号节 —— 那是改语义，不是改层级。

5. **标题 → 正文时留住 `\label`。** `\section{方法}\label{sec:method}` 设为正文后是 `方法\label{sec:method}`。
   现状实现会把 `\label` 一起丢掉（引用当场断），docmodel 不复制这个行为。
   （代价：`[短标题]` 会被丢掉 —— 短标题只对章节有意义，正文没有这个概念。）

6. **`mergePara` 只把「段落边界」变成一个空格**，每段自己内部的换行原样保留。
   所以「拆了又合」不是字节可逆的（会多一个边界空格）—— 但那个空格在 LaTeX 里**就是**段落边界，
   且内容一字不丢。这是设计，不是瑕疵。

7. **`reproject` 的认领是「顺序保持 + fail-safe」。**
   先按 `type+raw` 精确认领（保证「没动过的节点」一定认得回来），再同类型就近认领（覆盖「内容被编辑过」的块），
   剩下的一律发新 id。认不回来只是那一步历史对不上（少撤一步）；**乱认才会「撤到别的分支去」**。
   宁可少撤，不可撤错 —— 这条在实现里是硬约束。

8. **`undo()` 返回的是「凭据」，不是「结果」。**
   `undo()` / `redo()` **不碰文档**，只返回那条 tx；调用方 `doc.source = tx.before` 即可。
   这才是「可预测」的落点：不重放、不模拟、不猜。随机交错测试里每一步都断言
   `tx.after === 撤销前的内容` —— 一比就露馅，撤错一步立刻红。

9. **栈里不许有空转事务（`before === after`）。**
   两个来源：① rebase 重映射后，某步的改动被外部改动「吸收」了（前后变得相同）；
   ② coalesce 合并后净效果为零（窗口内打了又删回去）。
   留着它们的后果是「Ctrl+Z 按了没反应」—— 又是「不可预测」的一种。一律丢掉并计入 `gaps`。

10. **`rebase` 的落栈策略：撤销链必须停在「当前内容」上。**
    ① 先算 `curNew = merge3(extBefore, 当前内容, extAfter)` —— 这是用户眼前那份文件，
       **任何情况下都不许被静默改掉**；只有连它都合不了（外部改了同一处）才接受外部版本并计入 `gaps`。
    ② 逐条重映射每条事务的 `{before, after}`（`merge3` 是纯函数 ⇒ 原本相等的字符串映射后仍相等，
       所以「能合的那些」之间的链自动保持，不必也不许去猜）。
    ③ 从 `cursor-1` **往前**接、从 `cursor` **往后**接，各接出**连续的一段**：停下来就是停，
       不跳过、不猜。kept = 「当前那一步前后连续可用的那一段」，`base` = 它下面那一步的状态；
       空转事务（`before === after`）跳过不计入链，但计入 `gaps`。
    这样「不许撤错」（每一步的 before/after 都精确）与「不悄悄丢用户内容」（当前内容不动）
    同时成立。丢弃原因写进 `dropped`：`conflict` / `absorbed` / `unreachable` / `state-conflict`。

    ⚠ 走过的弯路（记下来，别再犯）：最初写的是「保留从栈底起连续的**前缀**，从断点起整段砍掉」。
    后果是链全断时 `cursor` 归 0 → `state()` 变成历史地板 → **等于把用户没撤过的编辑悄悄抹掉**。
    那是「撤错」的另一面：不是撤多了，是内容没了。随机交错跑到第 402 次迭代时才被抓出来
    （现场是「整篇正文被并成一段」—— 地板那份的换行结构与当前内容不同，`merge3` 拼出来的东西长那样）。
    当时那个「外部专用块」precondition 断言救了这一把：它把「测试前提被破坏」和「模块误判」
    分得清清楚楚。

11. **`rebase` 绝不清栈 —— 除非外部改动真的跟历史撞在同一处。**
    外部改动落在**别的块**上时，一条都不丢（`dropped === 0`）。
    随机交错测试里这是**构造性**的：文档里有一个「外部专用块」，本地随机操作一律不碰它
    及其紧邻，外部改动只打它。这条断言因此是在真验模块，而不是在猜。
    （踩过的坑：早先按「历史里记过的节点 id」挑远处的块，但 `reproject` 会重铸 id，
    于是挑中的偏偏是本地刚改过那一行；另外 `textyNodes` 含 `blank`，`setText` 打中专用块
    旁边的空行会让两者被段落聚合成一个多行节点 —— 两者都是**测试造错前提**，不是模块误判。已修。）

12. **`merge3` 是逐行对齐的，有已知边界**（文件头「已知边界」有完整复现）。
    外部把一段多行内容整段重写、而本地历史只动了其中一行时，会判成冲突并丢那一步。
    这也**只在撤销步数上付代价**（`gaps++` 且 UI 明说），内容一个字节都不会错。
    要根治得换成按相似度匹配的对齐（词级 diff）—— 记在这里，不在 P2 范围内。
